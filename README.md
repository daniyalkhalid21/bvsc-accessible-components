# BVSC accessible component library

![CI](../../actions/workflows/ci.yml/badge.svg)

**Live Storybook:** after your first push to `main`, GitHub Actions publishes it to `https://<your-github-username>.github.io/<repo-name>/` (see "Publishing" below). Replace this line with the real link.

An accessible React component library for **Boutique Veterinary Supply Company**, a small online shop selling syringes, feed supplements, grooming tools and pet health products. It targets **WCAG 2.2 AA** and follows the WAI-ARIA Authoring Practices.

**Why:** shoppers include clinic staff, farmers (often on phones, outdoors) and pet owners, including keyboard-only and screen reader users. The shop needs a reusable set of components for the catalogue and ordering flow that works for all of them.

## The demo page is a working (simulated) shop
There is no backend, but every control does something real: add to basket with stock limits, a Basket tab (change quantity, remove, clear), Place order through the confirm dialog, a My orders history, invoices, and a simulated sign in / sign out. Orders live in memory and reset on reload. This exercises the components together the way a real shop would.

## What's inside
Eight components, plus a skip link and a demo catalogue page that combines them:

| Component | Used for | APG pattern |
|---|---|---|
| Button | Add to basket, place order, remove (primary / secondary / danger, loading, icon-only) | Button |
| FormField set (TextInput, Select, Checkbox, RadioGroup, Textarea) | Order enquiry form with validation | Native HTML, Radio Group |
| Accordion | Delivery and returns FAQ | Accordion |
| Tabs | Product details (automatic activation) | Tabs |
| Table | Sortable price list | Table |
| Modal | "Confirm your order" (native `<dialog>`) | Dialog (Modal) |
| Menu | Account menu button | Menu Button |
| Toast | "Added to basket", errors | Alert / status (no APG toast pattern) |
| SkipLink | Skip to main content | WCAG technique G1 |

## Stack
Vite, React 18, TypeScript, Storybook 8 with `@storybook/addon-a11y`, axe-core, Vitest, Testing Library, user-event, vitest-axe. Plain CSS with CSS variables (`src/tokens.css`), no UI framework.

## Key decisions
- **Native first:** `<dialog>`, `<fieldset>`, `<table>`, `<button>`; ARIA only for tabs, menu and live regions.
- **Tabs use automatic activation** because panels are static and cheap; documented in the Tabs page.
- **Modal opens on the safe action** ("Back to basket") rather than "Place order".
- **Toasts live in two persistent regions** (`role=status`, `role=alert`) so announcements are reliable; errors never auto-dismiss; toasts never take focus.
- **Errors are never colour-only:** icon plus hidden "Error:" prefix; stock level is text.
- **Targets are 44px** (WCAG 2.2 minimum is 24px) for gloved or outdoor use.
- **Contrast checked at token level** with a script, because jsdom cannot evaluate rendered colour.

## Limitations
- The browser audit scans each story **in isolation** at one viewport, so it cannot catch problems that only appear in combination, at other zoom levels or with forced colours. Page-level axe rules (landmarks, h1, region) are scoped to the Demo page only, because a component story is not a page.
- **No screen reader testing has been done.** `docs/MANUAL_TEST_CHECKLIST.md` is blank for NVDA / VoiceOver results.
- Focus return, scroll lock and focus wrap in the Modal are tested in jsdom with a `showModal` polyfill, not in a real browser.
- **No manual screen reader testing (NVDA / VoiceOver) was performed.** Screen reader behaviour is covered only by following the APG patterns, testing the accessibility tree with Testing Library roles and names, and axe; the checklist tables for NVDA and VoiceOver are intentionally left blank.
- Automated tools find only a portion of accessibility issues. No claim of full WCAG 2.2 AA conformance is made; see `docs/WCAG_CONFORMANCE.md`.

## CI and publishing
- `.github/workflows/ci.yml` runs type check, tests, contrast, a Storybook build and the **real Chromium axe audit** on every push; it fails on serious/critical violations and uploads `AUDIT_LOG.md`.
- `.github/workflows/deploy-storybook.yml` deploys Storybook to GitHub Pages on push to `main`. Enable it once: repo **Settings → Pages → Source: GitHub Actions**.
- Alternatives: any static host serving `storybook-static/`; a Replit static deployment is preconfigured in `.replit`.
