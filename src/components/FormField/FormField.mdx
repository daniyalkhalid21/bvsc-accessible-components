# FormField

Labelled form controls: TextInput, Select, Checkbox, RadioGroup and Textarea. Hints and errors are wired with aria-describedby, invalid fields get aria-invalid, and errors are text with an icon (never colour only).

<Canvas of={Stories.OrderEnquiry} />

## When to use
<ul><li>Any form that collects information from customers.</li><li>The Order enquiry story shows an error summary that takes focus and links to each invalid field.</li></ul>
## When not to use
<ul><li>Placeholders as labels. Every control has a visible label.</li><li>Grouping unrelated controls in a fieldset.</li></ul>

## Usage
```tsx
<TextInput label="Email" type="email" required hint="We send the receipt here" error={errors.email} />
<RadioGroup legend="Delivery speed" name="delivery" options={opts} value={v} onChange={setV} />
```

## APG pattern followed
[Radio Group (and native HTML for the rest)](https://www.w3.org/WAI/ARIA/apg/patterns/radio/)

## Screen reader notes
Label, required state, hint and error are read when the control gets focus. The error text begins with the hidden word "Error:". The radio group is announced as a group with the legend as its name.

## Known limitations
<ul><li>aria-invalid and aria-required are not allowed on fieldset (found by axe, fixed), so a group error is exposed through aria-describedby only.</li><li>Validation is demonstration code in the story, not a validation library.</li></ul>
